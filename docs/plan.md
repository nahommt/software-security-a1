# Lifecycle Plan

**Application:** Car valuation service for a car dealership
**Language:** Python
**Status:** Requirements phase complete. Committed before any feature code.

This plan follows the chain:
asset → threat → requirement/control → lifecycle activity → test/evidence → gate decision.

---

## 1. Scope

Private sellers submit information and images of a car. The dealership responds with a price valuation. A seller can request a valuation report, generated by a separate service.

| Role | Type | Seeded accounts |
|---|---|---|
| Seller | Ordinary | `alice`, `bob` |
| Dealer | Privileged | `dealer` |

**Entity types:** Car (owner, make, model, year, mileage, description, images), Valuation (car, dealer, price, comment, timestamp).

**Out of scope:** registration, GUI, payments, email, public hosting. Synthetic data only. CLI client as UI.

### Functional requirements

| ID | Requirement | Role | Components |
|---|---|---|---|
| FR1 | Log in with username and password | Seller, Dealer | API |
| FR2 | Submit a car with information and images | Seller | API, Resource |
| FR3 | View own cars, filter by make | Seller | API, Resource |
| FR4 | View all submitted cars | Dealer | API, Resource |
| FR5 | Create a valuation for a car | Dealer | API, Resource |
| FR6 | Request a valuation report for own car | Seller | API, Processing, Resource |

### Non-functional requirements

| ID | Requirement |
|---|---|
| NFR1 | A seller cannot read or modify another seller's cars or valuations |
| NFR2 | Every request to the resource service is authorized, also from other services |
| NFR3 | Access tokens expire after 15 minutes |
| NFR4 | Requests without a valid token are rejected by default |
| NFR5 | All components run as separate containers, started with one command |

## 2. Architecture

See `docs/architecture.png` (source: `docs/architecture.drawio`).

| Component | Responsibility | Owns | Reachable from |
|---|---|---|---|
| `auth-gateway` | Authenticate, issue tokens, forward requests | Users, password hashes, signing key | Internet |
| `car-service` | Store data, enforce ownership on every request | Cars, images, valuations, reports | gateway, report-service |
| `report-service` | Generate one report per job | Nothing (stateless) | gateway |
| `carreport` | Helper package (wheel), formats report | Nothing | Imported by report-service |

**Networks:** `public` (gateway), `internal` (all three services), `auth-db` (gateway), `car-db` (car-service). report-service has no database network.

**Trust boundaries:**
- TB1 Internet → gateway
- TB2 gateway → internal services
- TB3 report-service → car-service
- TB4 report-service → carreport
- TB5 services → databases

## 4. Access control matrix

C = create, R = read. Anything not listed is denied. No update or delete.

| Subject | Car | Valuation | Report | User account |
|---|---|---|---|---|
| Seller, own | C, R | R | C, R | – |
| Seller, other's | – | – | – | – |
| Dealer | R (all) | C, R | – | – |
| auth-gateway | as user | as user | as user | R |
| report-service | R (job car) | R (job car) | C (job car) | – |
| car-service | C, R | C, R | C, R | – |
| carreport | – | – | – | – |

## 5. Token design

JWT via PyJWT, RS256 only. Gateway holds the private key; other services hold the public key.

| Token | Audience | Key claims | Lifetime |
|---|---|---|---|
| User token | auth-gateway | sub, role | 15 min |
| Service token | one internal service | sub, role, scope | 60 s |
| Job token | car-service | sub, car_id, scope, job_id | 120 s |

Binding: service = `aud`, resource = `sub` + `car_id`, action = `scope`, validity = `exp`.

## 7. Secure design principles

| Principle | Decision | Evidence |
|---|---|---|
| Least privilege | Each component gets only the rights it needs; report-service most restricted | T9, T14 |
| Complete mediation | Every car-service request is authorized, regardless of origin | T4, T8, T10 |
| Fail-safe defaults | Deny unless explicitly allowed; errors lead to denial | T2, T3, T13 |

## 8. Planted vulnerabilities

| ID | Vulnerability | CWE | Component | Breaks |
|---|---|---|---|---|
| V1 | Missing Authorization on `GET /cars/{id}` | CWE-862 | car-service | T8 |
| V2 | Path Traversal on `GET /cars/{id}/image` | CWE-22 | car-service | T15 |
| V3 | SQL Injection on `GET /cars?make=` | CWE-89 | car-service | T16 |
| V4 | Gateway and car-service both assume the other checks ownership in FR6 | Composition | gateway + car-service | T9 |

Approach: build the secure version first (all tests green), then plant each vulnerability in its own commit, demonstrate it, and fix it in a later commit.
