# Car Valuation Service

Software Security, Assignment 1.

## Purpose

Private sellers submit information and images of a car. The dealership responds with a price valuation. A seller can request a valuation report, generated by a separate service.

The full design (scope, architecture, assets, access control, threat model and lifecycle gates) is in [docs/plan.md](docs/plan.md).

## Repository layout

| Path | Component |
|---|---|
| `auth-gateway/` | Authenticates users, issues tokens, forwards requests |
| `car-service/` | Stores cars, images, valuations and reports; enforces ownership |
| `report-service/` | Generates one report per job (stateless) |
| `packages/carreport/` | Helper package (wheel) that formats reports |
| `scripts/` | Helper scripts (seed, checks) |
| `docs/` | Lifecycle plan and diagrams |

## Requirements

- Docker with Docker Compose
- OpenSSL (for generating keys and seed passwords)

All Python code, including tests and dependency locking, runs in `python:3.12-slim` containers.

## Commands

> Commands marked TODO are added in later tickets.

### Secrets

Generate the RS256 key pair and random seed passwords in `secrets/` (git-ignored). Existing files are kept:

```bash
./scripts/generate_secrets.sh
```

The files are passed to the containers as Docker secrets. `auth-gateway` gets the key pair, and only the seed job gets the seed passwords.

### Dependencies

Each service pins its dependencies with hashes in `requirements.txt` (and `requirements-dev.txt` for tests), generated from `requirements.in`. Images install them with `pip install --require-hashes --only-binary=:all:`. To update the lock files after changing a `requirements.in`:

```bash
./scripts/lock_dependencies.sh auth-gateway
```

```bash
./scripts/lock_dependencies.sh car-service
```

```bash
./scripts/lock_dependencies.sh report-service
```

### Build

Build the `carreport` wheel first. The script builds it in a `python:3.12-slim` container and writes it to `report-service/wheels/`:

```bash
./scripts/build_carreport.sh
```

Then build the images. `report-service` installs its PyPI dependencies from `requirements.txt` with hashes, and installs `carreport` with pip from the local wheel only (`--no-index --no-deps`), as declared in `report-service/requirements-carreport.txt`:

```bash
docker compose build
```

### Seed

Seed everything with one command:

```bash
./scripts/seed.sh
```

The script generates `secrets/` if it is missing, then runs two seed jobs without network access. The seed resets existing data, so the result is the same on every run.

- `auth-seed` creates exactly `alice`, `bob` (seller) and `dealer` (dealer). Passwords come from the git-ignored `secrets/seed_users.json` and are stored as bcrypt hashes.
- `car-seed` creates one synthetic car per seller (alice: Volvo V70, bob: Audi A4), each with one PNG image and one valuation by `dealer`.

### Run

```bash
docker compose up
```

The gateway is published on `http://localhost:8000`. No other service is exposed. `car-service` is only reachable on the `internal` network and accepts only service tokens and job tokens with `aud=car-service`. `report-service` is only on the `internal` network, has no database and no private key, and accepts `POST /jobs` with a service token (`aud=report-service`, scope `jobs:create`) and a job token in the body.

Log in and call a protected endpoint:

```bash
curl -s -X POST localhost:8000/login -H 'Content-Type: application/json' -d '{"username": "alice", "password": "<password from secrets/seed_users.json>"}'
```

```bash
curl -s localhost:8000/me -H 'Authorization: Bearer <access_token>'
```
